# 定期実行を作る・直すときの手順

慧が、定期実行（決まった時刻に自動で動く仕事）を作る・直す・止めるときに読む。普段は読まない。

## 手順
1. **確認** — 繰り返す定期実行の新規作成・指示文の書き換え・削除は、先にふみさんに確認する（`.claude/CLAUDE.md` の「先にふみさんに確認する操作」）。一覧を見るだけなら確認は要らない
2. **置き場所** — 何を読み書きするかで選ぶ
   - 経験ログを読み書きしてpushする仕事、ふみさんへの報告が目的の仕事：この会話に届く形にする
   - コネクタもフォルダも要らない仕事（制度の案内など）：新しい会話で動く形でもよい。必要な前提は指示文に書く
   - PCのブラウザが要る仕事：この会話からは作れない。ふみさんがPCで動く会話から作る
3. **指示文** — 最初に読むファイル（`.claude/skills/<名前>/SKILL.md` と経験ログ）と、報告の形（要点一言＋箇条書き）を書く。メールアドレス・家族構成・電話番号・個別のURLは書かない
4. **届いたか** — 作ったら、最初の報告がふみさんに届いたかを本人に確かめる。「実行の成功」と「本人に届いた」は別
5. **記録** — 采が組織図と布陣の棚卸しに使うので、作った・止めたことを慧の経験ログに1行残す

## これまでの学び（2026-11-12 に慧の経験ログから移した）

### 新しいセッションで動く定期実行の報告は、ふみさんに届いていなかった（2026-11-02）
- 週次AIレポートは2か月間、毎回「成功」していたが、報告は別のセッションに残るだけで、ふみさんは一度も読めていなかった。通知の設定があっても届いていなかった
- 「実行の成功」と「本人に届いた」は別物。定期実行を作ったら、最初の報告が本人に届いたかを本人に確認する
- 対処：報告が目的の定期実行（AIレポート・資産レビュー・確定申告の案内）は、この会話に届く形に作り直した。ログの読み書きもできるようになる。カレンダー経由でLINEに届く毎晩の指示はそのまま

### 定期実行の置き場所は「何を読み書きするか」で選ぶ
- ログを読み書きしてpushする仕事（部長会・育成評価）は、このセッションに届く形にする。新しいセッションで動く形では、リポジトリが無く、ログを読めない
- コネクタが要る仕事は、新しいセッションの形で作ると、コネクタが付かない。作った後に、ふみさんがclaude.aiの画面でコネクタを追加する必要がある。手順を案内すれば数分で済む
- コネクタもリポジトリも要らない仕事（制度の案内など）は、新しいセッションの形で、必要な前提をプロンプトに書き込んでおけばよい

### 定期実行は、ロール定義のブランチを読めないことがある
- ロール定義と経験ログは作業ブランチにだけあり、mainには無い。新しいセッションで動く定期実行は、`~/.claude/skills/` を読もうとしても見つからない
- 定期実行には、ブランチを指定して読む手順と、読めない場合に備えてプロンプト内に要点を持たせる（2026-10-30、毎晩の指示の定期実行で対応）
- mainへの取り込み（PR）はふみさん判断で**保留**（2026-10-30）。指示があるまで再提案しない

### 「このカレンダーに入るはず」という前提で探さない（2026-11-14）
- 毎晩の指示は、ラウンドを「ゴルフ」カレンダーだけで探していた。実際は2回続けて別のカレンダーに入っていて、朝の格言もスコアカードの依頼も出なかった
- 予定を探す定期実行は、全部のカレンダーから題名で探す。数えないもの（自分が作った予定、練習など）を指示文に書く
- 2026-11-14 ふみさんの承認で、毎晩の指示の指示文を直した。変えたのはラウンドの見つけ方だけ
